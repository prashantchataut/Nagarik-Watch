# Nagarik Watch Full UI/UX Redesign Audit

Date: 2026-08-28

## Scope

The repository route inventory contains:

- 80 public page routes;
- 35 custom operations-admin routes;
- 51 API routes;
- 2 feed routes.

The audit reviewed the route matrix, the shared public shell, homepage composition, article layout, desk/index families, institutional pages, reader utilities, Patro/calendar, auth/journalist shells, custom operations admin, Payload CMS theme, ad inventory, live-data override model, and content-authority selection.

This work is intentionally implemented through shared families rather than 115 independent page skins. A route that already uses a family component inherits the redesign and future fixes from that component.

## Critical findings

### P0 — calendar failures could become plausible-looking false data

Previous date helpers used two unsafe fallbacks:

- a failed BS month-length lookup returned 30;
- a failed AD→BS conversion returned the Gregorian year/month/day in a BS-shaped object.

That behavior was removed. Unsupported values now fail explicitly. “Today” is resolved from Asia/Kathmandu civil time, and calendar AD labels/weekday calculations are normalized for Kathmandu rather than trusting raw UTC date components.

Calendar publication validation now checks:

- supported BS year;
- actual month length for the selected year/month;
- Nepali and English names;
- holiday type;
- duplicate event rows.

The phase-2 implementation supersedes the earlier structured-editor approach: the normal workflow is now provider-driven calendar synchronization with validated last-known-good storage. Staff can trigger a sync, but they do not hand-author the public holiday/festival year as JSON.

### P0 — live content authority can diverge if the deployment is misconfigured

The repository contains a preview/emergency desk store as well as the canonical Payload CMS. That is a legitimate migration/recovery architecture but becomes dangerous if both are treated as normal production editorial authorities.

Existing live safeguards are retained:

- `.env.example` defaults `CONTENT_SOURCE=payload`;
- a declared live launch rejects a non-Payload content source;
- Payload configuration fails closed rather than silently falling through to the desk store;
- starter inventory is documented as non-production.

The redesign contract now states this explicitly: mutable production news belongs to the canonical CMS; seed/store inventory is development, preview, migration or emergency infrastructure only.

### P1 — public chrome consumed the page before editorial content

The masthead previously supported a desktop utility band, a logo/leaderboard row, the desk nav and a topic row. The redesign reduces primary public chrome to:

1. one warm-paper masthead;
2. one sticky Civic Crimson desk rail.

Topic discovery moves into editorial surfaces. The masthead leaderboard placement was retired from the ad inventory rather than reintroduced merely to satisfy the old ad registry.

### P1 — homepage and desk pages had weak editorial hierarchy

The opening package is now centered, text-first and photo-dominant. Supporting stories sit beneath it. Shared desk headers are centered and use large Mukta display type rather than generic left-aligned title blocks.

Role-aware homepage sections remain dynamic: news desks, compact desks, split/business, photo desks and voice/opinion layouts are preserved rather than converting all desks to one universal card.

### P1 — secondary pages repeated a generic “bordered card” visual language

Shared changes flatten and standardize:

- desk holding states;
- index rails;
- contact lanes and contact rail;
- team roster and standards links;
- advertising principles;
- disabled membership state;
- utility directory.

Rules, typography, whitespace and content order now provide hierarchy before boxes do.

### P1 — utility navigation was duplicated and spatially expensive

The general utility shell no longer uses a permanent desktop sidebar. Tools use a horizontal, scrollable service rail and a full-width workspace.

The embedded Patro route no longer repeats its own Patro tool nav beneath the main site desk rail. The standalone Patro host retains a dedicated product header/navigation because it does not inherit the main public shell.

### P1 — operations admin and Payload looked like unrelated products

Both internal surfaces now share warm newsroom neutrals, flat task-oriented structure, larger headings and a restrained Civic Crimson active state.

The custom admin sidebar is widened for Nepali labels and receives a strong inset active marker. The content column is wider and workflow strips are flattened. Payload collection/document screens receive the same warm paper direction, larger page titles and calmer table/field spacing.

## Data and hardcoding policy

The audit distinguishes immutable product constants from mutable publication data.

Allowed in source code:

- navigation structure;
- labels and route IDs;
- BS month names;
- zodiac identifiers;
- validation bounds tied to a library;
- ad placement definitions.

Not allowed as live production authority in page components:

- current news inventory;
- current stock/forex/gold values;
- live scores;
- current rashifal edition;
- current holiday/festival schedule;
- invented fallback dates.

The homepage already uses the content source and editorial data model. That plumbing was preserved. The redesign does not replace dynamic publishing with a static mock homepage.

## Advertising changes

The masthead leaderboard, latest-top leaderboard and trending-top leaderboard were removed from active placement inventory. Latest and trending retain a lower-density inline commercial opportunity rather than placing an ad before the destination header.

The repository ad audit passes after this change.

## Accessibility changes and guarantees

The redesign keeps or strengthens:

- skip/main landmark structure;
- keyboard-operable masthead menus and mobile drawer;
- visible focus states;
- semantic destination headings;
- source/freshness text for live data;
- horizontal rails that can scroll rather than overflowing the page;
- DOM order with primary Patro calendar work before its reference sidebar;
- explicit calendar unavailable states;
- structured labels in the calendar admin editor.

## Performance direction

- lead media remains the only priority homepage image;
- image dimensions/aspect-ratio space is reserved;
- ad slots remain registered with dimensions;
- optional homepage/live modules remain independently fallible;
- the redesign does not add animation libraries, carousels or layout-measuring client scripts.

## Deployment gate

Before production deployment, run with normal dependency/network access:

```bash
corepack pnpm install --frozen-lockfile
pnpm format:check
pnpm lint
pnpm typecheck
pnpm test
pnpm verify:static
pnpm --filter @nagarikwatch/web build
pnpm --filter @nagarikwatch/db test
pnpm test:e2e
```

For a declared live launch, verify that `CONTENT_SOURCE=payload` and the Payload public/admin URL are configured before any editorial publishing test.
