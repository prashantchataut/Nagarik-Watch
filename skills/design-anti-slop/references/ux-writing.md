# UX Writing & Microcopy Patterns

Complete catalog of copy patterns that signal generic AI generation, with authentic alternatives.

## Headlines

### High-Confidence Slop

| Slop pattern | Why it's slop | Authentic alternative |
|---|---|---|
| "Empower Your Business" | Vague, could apply to anything | "Cut API response time 80%" or "Ship features 3x faster" |
| "Transform Your Workflow" | Empty transformation claim | "Automate 90% of deployment steps" |
| "Revolutionize Your [X]" | Hyperbolic, never delivered | "Replace 4 tools with 1" |
| "Unlock Your Potential" | Meaningless self-help language | "Get from idea to production in 20 minutes" |
| "Seamless Experience" | "Seamless" is the most overused word in SaaS | "Works where you already code" or "No config needed" |
| "In Today's Fast-Paced World" | Filler preamble; delete entirely | Start with the actual point |
| "Take Control of Your Future" | Vague, aspirational, no substance | "See every commit's impact on revenue" |
| "The [X] Platform for [Y]" | Template headline formula | Say what it does: "Real-time error tracking that doesn't spam you" |
| "Reimagining [X]" | Empty buzzword | "We rebuilt [X] from scratch because [specific reason]" |

### Headline Quality Test

Run the **swap test**: replace your product name with a competitor's. If the headline still works, it's too generic.

Run the **opposite test**: state the opposite of your headline. If the opposite is obviously absurd ("Slow Your Business Down!"), the original was too vague to be meaningful.

## Body Copy

### High-Confidence Slop

| Slop pattern | Why it's slop | Authentic alternative |
|---|---|---|
| "In order to" | Wordy | "To" |
| "Due to the fact that" | Wordy | "Because" |
| "Has the ability to" | Wordy | "Can" |
| "It's important to note that" | Filler; if it's important, just say it | Delete entirely |
| "Leverage" | Buzzword | "Use" |
| "Synergistic" | Buzzword | "Cooperative" or just describe the interaction |
| "Paradigm shift" | Buzzword | "Major change" or just describe the change |
| "Cutting-edge" | Vague modifier | Name the specific technology or capability |
| "State-of-the-art" | Vague modifier | Name what makes it current |
| "World-class" | Unverifiable claim | Specific evidence or delete |
| "Industry-leading" | Unverifiable claim | Specific metric or ranking |

### Body Copy Principles

- **Be direct**: Skip preambles and meta-commentary. Lead with the actual point.
- **Be specific**: Replace generic terms with concrete examples. Name specific things instead of "items," "things," "data."
- **Be authentic**: Vary sentence structure and length. Use active voice. Write in a voice appropriate to context.

## CTAs (Calls to Action)

### High-Confidence Slop

| Slop pattern | Why it's slop | Authentic alternative |
|---|---|---|
| "Get Started" | Vague; start what? | "Start Free Trial" "Create Your First Project" |
| "Learn More" | Lazy; tells user nothing about what they'll learn | "See Pricing" "Read the Docs" "Watch the Demo" |
| "Try for Free" | Weak; doesn't convey value | "Start 14-Day Trial" "Build Your First App Free" |
| "Contact Us" | High friction; feels like a sales call | "Talk to an Engineer" "Get a Quote" |
| "Submit" | Mechanical; what happens after? | "Send Feedback" "Publish Post" "Save Changes" |
| "Click Here" | Accessibility failure; meaningless out of context | Use descriptive text that makes sense as a standalone link |
| "Sign Up" | Vague about commitment | "Create Account" "Start Building" |
| Gradient button with excessive shadow | Visual noise; the default "make it pop" approach | Simple, clear button styling; content makes it compelling |

### CTA Quality Test

**The action test**: Does the CTA text describe what happens next? "Get Started" fails because it doesn't say what you're starting. "Create Account" passes because it describes the next step.

**The specificity test**: Could this CTA belong to any product in any industry? If yes, it's too generic. "Start Free Trial" is specific to trial-based products. "Download Report" is specific to content.

## Feature Descriptions

### High-Confidence Slop

| Slop pattern | Why it's slop | Authentic alternative |
|---|---|---|
| "Powerful [feature name]" | "Powerful" adds nothing | Name the specific capability or outcome |
| "Intuitive interface" | Every product claims this | "No training needed" or "Design in 3 clicks" |
| "Robust [X]" | Empty adjective | "Handles 10M+ records" |
| "Flexible" | Could mean anything | "Custom fields, custom views, custom workflows" |
| "Scalable" | Every product claims this | "From 1 to 100K users with no config changes" |
| "Comprehensive" | Means "has a lot of stuff" | List the specific capabilities |
| "End-to-end" | Overused | Name the start and end points |

### Feature Description Test

**The competitor test**: Could a competitor make the same claim? If yes, it's not a differentiator.

## Social Proof

### High-Confidence Slop

| Slop pattern | Why it's slop | Authentic alternative |
|---|---|---|
| "Trusted by industry leaders" | Unverifiable; who? | "Used by engineers at Stripe, Vercel, and Linear" |
| "10K+ users" | Vanity metric without context | "10,342 teams deploy weekly" |
| "99% satisfaction" | Made up or cherry-picked | "4.8/5 on G2 from 2,340 reviews" |
| Generic testimonial with stock photo | Obviously fake | Real name, real role, real company, real outcome |
| Logo wall of companies | Unverifiable relationship | "See how [Company] reduced deploy time 60%" |
| "Featured in [Publication]" | Often just a mention, not an endorsement | Link to the actual article |

## Error Messages & Empty States

### High-Confidence Slop

| Slop pattern | Why it's slop | Authentic alternative |
|---|---|---|
| "Something went wrong" | Tells user nothing | "Payment failed: your card expires next month" |
| "Please try again later" | Dismissive | "Rate limit reached. Try again in 60 seconds." |
| "Error: null" | Developer-facing error in production | "We couldn't load your data. Refresh to try again." |
| "No data" | Unhelpful empty state | Explain what goes here and how to add it |
| "Coming soon" | Overpromised | "We're building this. Want early access?" |

### Error Message Principles

- Explain what happened (specific, not vague)
- Explain why it happened (if known)
- Tell the user what to do next (actionable)
- Use human language, not system language
- For empty states: explain what belongs here and how to populate it

## Microcopy Patterns

### High-Confidence Slop

| Slop pattern | Why it's slop | Authentic alternative |
|---|---|---|
| "Don't worry" | Condescending | Just fix the problem |
| "Oops!" | Childish for most products | State the issue directly |
| "Hang tight" | Patronizing | "This takes about 30 seconds" |
| "Are you sure?" | Vague confirmation | "Delete this project? This cannot be undone." |
| "Yay!" | Unprofessional for most contexts | Use appropriate tone for the product |
| "We're sorry for the inconvenience" | Generic corporate apology | "The upload failed. Try again or drag your file here." |

## The Meta-Commentary Test

Delete any sentence that:
- Describes the document itself ("This guide will help you...")
- Restates the heading ("Our powerful features are...")
- Acknowledges the user's presence ("Welcome to our platform!")
- Apologizes for the content ("In this section, we'll briefly cover...")

If removing the sentence changes nothing about the reader's understanding, it's slop.
